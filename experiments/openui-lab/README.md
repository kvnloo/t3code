# OpenUI Lab experiment (not yet packaged)

This downstream experiment adds opt-in rendering for `openui-v1` fenced blocks in the web/Electron chat transcript. The fence remains ordinary stored Markdown, so replay, remote transport and non-supporting clients retain the original source. Mobile currently shows that source plus the agent's normal Markdown summary; this is not native mobile support.

## Catalog v1

Stock `@openuidev/react-lang` and `@openuidev/lang-core`, pinned to 1.0.2, provide the language/parser/runtime. The deliberately small `Report` catalog supports a title, summary, metric cards, a table and percentage meters. It has no tool provider, action callbacks, state callbacks, HTML, remote assets or links. A report is rendered only after the user clicks **Render report**. **Show source** reverses that choice. The runtime loads lazily.

The stock parser is permissive; the wrapper rejects incomplete/unresolved programs, parser errors, queries, mutations, state, invalid percentages, excessive payloads and table row-width mismatches. Literal text is rendered through React, not injected as HTML. Maximum source length is 64 KiB.

## Generation

`OpenUiReport.tsx` exports `openUiReportPrompt`, generated by the real catalog's `library.prompt()`. Give it to the model as generation instructions. The output must include an `openui-v1` fence and a normal Markdown summary. Do not teach a second homemade DSL.

Example (synthetic test data, not experiment measurements):

````markdown
```openui-v1
root = Report("Test results", "Focused parser suite", [{label: "Passed", value: "12"}], ["Suite", "Result"], [["Parser", "pass"]], [{label: "Pass rate", value: 100}])
```
Parser: 12 passed.
````

## Validation

`report.test.ts` contains four focused Node tests exercising the actual stock parser and React server renderer: valid rendering; malformed/unresolved/unknown/tool-bearing input; interrupted/replayed input; escaping/input limits. These are not browser or integrated T3 tests.

The bounded generation pilot is run with:

```sh
python3 experiments/openui-lab/generation-pilot.py \
  --endpoint http://100.113.138.100:11530/v1 \
  --model qwen3-4b-q4km \
  --catalog /mnt/zer0models/project-artifacts/t3-openui-lab/20261101/catalog-prompt.txt \
  --out /mnt/zer0models/project-artifacts/t3-openui-lab/20261101/generation
```

It compares the same model and report data in alternating OpenUI/HTML order, preserving prompts, SSE chunks, provider token usage, TTFT, completion time and finish reason. It is a **generation-only pilot**, not an end-to-end comparison with T3's actual `html_preview`/`html_render` transport. It does not measure first useful paint, accessibility, bundle overhead or correction rates. No speedup claim follows from it.

## Remaining before dogfood installation

- Update the workspace lockfile using the fork's required Node26.12.1/pnpm12.14.0 toolchain and install dependencies in the isolated worktree.
- Run focused repo tests/typecheck/lint, real client streaming/fallback/reload tests and review screenshots.
- Add a real composer entry point for copying/including the generated catalog instructions; a versioned fence alone is not a complete discoverable generation workflow.
- Build an isolated desktop product identity with independent app id, Electron userdata/session/single-instance identity, backend home, ports, protocol registration and disabled upstream updater. Do not install by renaming a production AppImage.
- Complete matched real-generation and integrated artifact comparisons. Run the exact installed binary and verify identity/storage isolation before handing it to the owner.

No separate app has been installed. The current live T3 installation and data are untouched.
